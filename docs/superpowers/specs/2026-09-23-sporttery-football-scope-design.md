# 全部竞彩足球赛事适用范围设计

- 日期：2026-09-23
- 状态：聊天方案已确认；本文待用户审阅
- 目标：将五大联赛限定改为中国体育彩票竞彩足球官方赛事范围。

## 1. 范围与非目标

赛事资格以中国体彩官方竞彩足球赛事清单为依据，不再以国家、地区、赛事名称、俱乐部或国家队类型设置白名单。其他联赛、杯赛、洲际赛事和国家队赛事只要进入官方清单，均属于项目业务范围。

不包含传统足彩胜负彩、任选九、篮球或自动下单。本次扩大赛事范围，不新增半全场等当前模型未实现的玩法，也不承诺每场比赛都有数据或推荐。

区分三件事：

1. **业务范围**：该场比赛是否由官方列入竞彩足球清单。
2. **可分析性**：是否具有可追溯、口径正确且适用的历史数据。
3. **可推荐性**：是否仍在售、玩法可用、数据新鲜、映射唯一且通过质量和风险门槛。

离线预测和回测允许分析非在售历史比赛，但其输出不能作为赛事官方开售的证明。赛事或玩法销售资格未经官方确认时不得输出正式投注建议。

## 2. 当前实现与方案选择

已检查的限制分布在 `model_core.py`、`fetch_match_data.py`、`backtest_model.py`、`contracts.py`、预测及回测 Schema，以及 README、流程、ADR 和 skill 文档中。当前模型默认俱乐部联赛、七月赛季边界和非中立主场，历史比分没有明确排除加时与点球。

备选方案：

- 仅修改文案和白名单：改动小，但不能解决杯赛比分、中立场和数据覆盖问题，不采用。
- 官方赛事入口 + 通用数据契约 + 保守的数据质量门槛：采用。复用已有流程，允许更多赛事输入，但拒绝不可靠数据。
- 一次接入覆盖全球的多家实时供应商并重建模型：超出本次范围，且供应商覆盖及授权尚未核实，不采用。

## 3. 数据流与职责

`官方竞彩足球清单 → 赛事与玩法销售校验 → 官方比赛 ID`

`历史数据适配器 → 标准化比赛上下文与常规时间赛果 → 数据质量校验 → ELO/泊松预测`

`官方比赛 + 预测 → 唯一身份匹配及新鲜度校验 → EV/仓位计算 → JSON 与 Markdown 报告`

保留现有脚本职责，不新增服务。官方数据负责竞猜资格，历史数据负责统计输入；两者通过比赛 ID、球队映射和开球时间关联。用户手填 `lottery_match_id` 本身不是官方资格证明。

## 4. 通用契约与兼容性

- `competition_code` 改为非空稳定标识，不再使用五大联赛枚举。供应商代码和官方赛事标识不得默认等价。
- 原五大联赛名称表保留为显示名称映射，不再称为支持范围；未知赛事使用显式名称或代码展示。
- 增加比赛上下文：球队类型（俱乐部／国家队）、赛事类型（联赛／杯赛／其他）、场地属性（主场／中立／未知）、比分口径（常规时间）。未明确的上下文不能静默解释为已确认。
- 稳定球队和比赛 ID 携带来源语义；来自不同供应商的同号 ID 不直接合并。跨供应商映射必须显式、唯一且可追溯。
- 新输出采用升级后的契约版本，运行时校验与 JSON Schema 同步。旧 2.0 五大联赛输出保持可读，但不自动补齐未知场地或比分口径后用于正式建议；历史输入能够经适配器核实语义时可重新生成新预测。
- 保留现有五大联赛 CLI 基本用法；涉及新上下文的参数与迁移要求在 README 给出。

## 5. 历史数据与来源

保留 football-data.org 适配器和显式历史快照入口。移除 CLI 的赛事 `choices` 限制不代表供应商支持所有赛事；接口无权限、赛事不存在、无数据时输出明确错误，不伪造回退数据。

标准历史快照需要记录来源、抓取时间、球队类型、赛事/样本范围、场地属性和比分口径。文件修改时间不能代替可验证的数据观测时间用于正式建议。原始数组仍可作为离线开发输入，但缺少来源或上下文时不得通过正式质量门槛。

样本池必须显式声明适用范围，不混用俱乐部与国家队样本。跨赛事历史允许进入经过说明的同类样本池，必须记录其组成；不把没有可比依据的独立联赛评级直接视为统一强度。无法建立可比依据时返回数据不足，而不是用相同初始 ELO 宣称双方可比较。

赛季选择尊重显式 `--season`，并在实时取数中实际使用。不能将七月赛季推断无条件应用到自然年联赛或届次杯赛；无法确认时要求显式选择，不猜测届次。

## 6. 比分口径与模型处理

本次预测的胜平负、让球胜平负、总进球和比分以常规时间（含伤停补时，不含加时及点球）为统一建模口径。落地时需要根据官方玩法规则和供应商字段文档核实映射；未经官方/提供方确认的映射不得作为实现依据。

- 杯赛历史不能直接把含加时或点球的最终比分作为常规时间比分。
- 供应商能明确提供常规时间比分时提取该字段；存在加时/点球且不能还原常规时间赛果时拒绝或剔除该记录，并输出原因和数量。
- 比分须为非负整数，禁止把小数比分截断后使用。
- 中立场历史更新 ELO 时取消主场优势；中立目标比赛的 ELO 期望与进球基准均不施加主场优势，不能只修改一处。
- 中立进球基准使用所选同类样本池双方合并均值。场地未知时不得当成普通主场通过质量门槛。
- 国家队和俱乐部的样本与参数配置分离，暂复用统计计算实现，不恢复旧的静态国家队评级、主观评分或固定世界杯参数。
- 默认参数仍标记为待走步回测校准的基线，不声称扩展范围等于精度已得到验证。

## 7. 错误关闭和报告

保留既有过期、停售、截止时间、赔率完整性、球队匹配、样本量及 EV 检查。对新增情形给出机器可读原因及中文说明：来源无法核验、上下文缺失、常规时间比分不明、样本池不适用、历史覆盖不足、赛事未确认和玩法销售未确认。

结构无效或无法构建有效历史时返回结构化错误；可诊断但质量不达标的结果标记 `insufficient`，不能进入推荐。报告不得将诊断性概率呈现为可下注建议。没有推荐时保留拒绝原因，不生成替代赔率。

对比赛与玩法分别检查销售资格，缺失玩法状态不能仅凭比赛仍在售就视为该玩法可投注。不在官方清单的预测不进入推荐流程。

## 9. 验收标准

1. 非五大联赛、杯赛和国家队的有效测试输入不因赛事代码被拒绝；空代码仍被拒绝。
2. 不在官方竞彩足球清单、玩法未确认在售或已过期的比赛不产生建议。
3. 中立场在历史 ELO、目标 ELO、进球分布及回测基线中语义一致；未知场地不静默按主场处理。
4. 含加时/点球、无法确定常规时间比分的历史不能污染预测或回测。
5. 俱乐部和国家队样本不混用；跨池数据不因样本数量足够就绕过适用性检查。
6. 原五大联赛取数/预测基本命令仍可使用；旧输出兼容边界明确，过期或缺新上下文的旧数据不能绕过质量门槛。
7. 未覆盖赛事和无权限接口返回清晰错误；不声称实时供应商覆盖全部竞彩足球。
8. 走步回测只使用目标开球前的数据，报告跳过原因；测试覆盖非五大联赛和中立目标场景。
9. 文档、skill、Schema、CLI 和报告名称不再将五大联赛列为唯一范围；历史 ADR 与示例允许保留相关名称。

验证以可重复离线固定数据为主，模拟供应商错误和官方停售场景；不依赖真实付费 token，不把离线通过当作实时覆盖证明。具体测试命令在实现计划中依据项目规则确定。
