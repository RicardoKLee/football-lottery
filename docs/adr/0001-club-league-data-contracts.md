# ADR 0001：五大联赛数据契约与错误关闭

- 状态：已接受
- 日期：2026-08-25
- 受众：预测脚本、投注脚本和 skill 维护者
- 前置条件：Python 3.9+；实时运行需要数据提供方凭据和网络访问

## 背景

项目原实现把国家队元数据、预测 Markdown、竞彩赔率和投注计算耦合在脚本中。俱乐部联赛需要稳定球队标识、主客场信息、赛季历史和可验证的赔率时效。缺失数据不能通过静默默认值或模拟赔率补齐。

## 决策

1. 项目只支持英超、西甲、德甲、意甲和法甲，不保留世界杯或国家队兼容层。
2. `model-prediction`、`odds-snapshot` 和 `betting-report` JSON 是唯一机器接口；Markdown 仅作为派生展示。
3. 比赛和球队必须保存 provider 稳定 ID。名称只用于展示和严格别名匹配，不使用包含关系模糊匹配。
4. 俱乐部强度从按时间排序的历史赛果计算 ELO；主场优势进入 ELO 期望和进球参数。
5. 联赛平均进球和球队近期攻防从输入历史动态估计，不使用世界杯固定总进球基准。
6. 正式投注只接受真实、未过期、仍在售的赔率。任何关键字段缺失时返回拒绝原因，不生成赔率。
7. EV 使用模型概率及显式概率折减计算。市场去抽水概率仅作为对照，不以固定权重混入模型概率。
8. 凯利仓位基于 bankroll 计算，设置单项和总敞口上限，未分配资金必须保留。
9. 串关默认关闭；显式启用时只组合不同 `match_id`，并披露独立性假设。

## 备选方案

- 保留世界杯 profile：被否决。用户明确要求删除，且国家队数据与俱乐部数据没有必要共享运行时兼容层。
- 继续解析 Markdown：被否决。格式变化会导致字段静默丢失，无法可靠校验数据契约。
- 缺赔率时生成估算赔率：被否决。估算赔率不能证明市场真实可投注，也不能用于 EV 计算。
- 第一版直接实现完整 Dixon-Coles 或分层模型：暂缓。当前目标是完成数据与完整性迁移；模型接口允许后续在走步回测后替换。

## 影响

- 旧版预测 Markdown 不能直接进入投注脚本，需要重新生成结构化预测。
- 没有数据提供方 token 时可以用显式快照开发，但快照必须携带来源和时间；过期快照不能产生正式建议。
- 赛季早期或升班马历史不足时会出现“无推荐”，这是预期行为。
