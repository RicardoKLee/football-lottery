# ADR 0002：全部竞彩足球赛事适用范围与统一契约

- 状态：已接受（替代 ADR 0001 的赛事范围决策）
- 日期：2026-09-28
- 受众：预测脚本、投注脚本、回测和 skill 维护者
- 前置条件：Python 3.9+；单一契约模型

## 背景

ADR 0001 最初将项目硬编码限制在欧洲五大联赛（英超、西甲、德甲、意甲、法甲）。然而中国体育彩票官方竞彩足球在售赛事实际覆盖更广泛的俱乐部联赛（如日职联、葡超等）、杯赛（如欧冠、足总杯）以及国家队赛事（如世界杯、欧洲杯预选赛）。
为了使系统能够合法适用于体彩官方在售的全部竞彩足球赛事，同时维持高标准的数学严密性与生产安全底线，需要将赛事范围从硬编码的五大联赛扩展至以中国体育彩票官方竞彩足球清单为准，并重构统一数据契约。

## 决策

1. **业务适用范围与边界**：
   - 支持范围以中国体育彩票官方竞彩足球实际在售清单为准。
   - 包含竞彩足球全部在售赛事（其他俱乐部联赛、杯赛、洲际比赛、国家队赛事）。
   - 严格限定在竞彩足球四项主流玩法：HAD（胜平负）、HHAD（让球胜平负）、TTG（总进球）、CRS（比分）。
   - 明确排除传统足彩（十四场胜负彩、任选九场）、竞彩篮球以及任何形式的自动代投/下单。

2. **单一当前契约与无历史兼容层**：
   - 彻底废除五大联赛代码白名单硬限制，系统接受任意官方赛事代码。
   - 引入标准 `match.context` 对象，包含四个必填枚举：`team_type`（club/national）、`competition_type`（league/cup/other）、`venue`（home/neutral）、`score_basis`（regulation）。
   - 坚持单一契约原则，不维护向后兼容历史版本的读取分支；旧版数据产物需使用当前脚本重新生成。

3. **严格的 Fail-Closed 安全关闭与来源语义**：
   - 证据不可验证时一律 unknown，不能自动推定或提升凭证状态。
   - 数据快照必须携带明确的 `provider`、`source_url`、`fetched_at`、`provenance_status`（verified/unverified）与 `sample_pool`。
   - 推荐准入实施双层门槛：官方清单核实（`official_listing.status == "confirmed"`）与玩法销售状态核实（`market_status[market] == "open"`）。未确认或停售玩法必须安全跳过，绝不编造、模拟或估算赔率。
   - 开球时间容差由旧版的 6 小时收紧为 15 分钟，超出容差必须重新获取实时数据。

4. **常规时间比分与样本池隔离**：
   - 比赛比分统一为常规时间（含伤停补时）90分钟结果，剔除加时赛与点球大战比分；比分必须为非负整数。
   - 俱乐部样本池与国家队样本池严格物理隔离；跨赛事样本池必须显式声明并经过图连通性验证。
   - 样本图连通性与统计指标只允许使用目标比赛开球时间（kickoff_utc）之前的历史数据，杜绝前视偏差与未来信息泄漏。

5. **中立场与主场优势消除**：
   - 当 `match.context.venue == "neutral"` 时，双向取消 ELO 期望胜率修正与泊松进球期望的主场加成；
   - 场地状态为 `unknown` 时安全标记为 `insufficient` 并拒绝输出有效推荐。

6. **模型核心与回测指标命名统一**：
   - 预测模型标识由旧版特定命名统一调整为通用 `football-elo-poisson`。
   - 走步回测指标键统一命名为 `football_elo_poisson`，支持目标比赛上下文透传。

## 备选方案

- 保留旧版五大联赛白名单并作为独立分支运行：被否决。维护双分支或版本兼容层会引入契约漂移和维护陷阱，增加安全隐患。
- 允许通过 CLI 参数由用户直接声明数据来源已核实（provenance_status="verified"）：被否决。JSON 文件或命令行声明不能作为真实凭证，必须通过适配器或离线核验逻辑确保证据链闭环。
- 官方未在售但赔率存在时使用估算赔率推荐：被否决。违反国家体育彩票业务准则，且估算赔率无法进行合法的保守 EV 评估。

## 影响

- 既有历史预测文件与赔率快照不兼容当前契约，用户需要使用最新 CLI 重新抓取与生成。
- 官方未在售、历史场次不足或来源凭证未验证时，系统将如实返回空推荐并记录拒绝原因。
- 业务范围扩展至全部官方竞彩赛事，但实际预测能力受限于所接入数据源的覆盖深度与赛季权限。
